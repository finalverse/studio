# S3-A Report Schema — `finalverse.asset-intelligence/v1`

Machine-readable schema: [`schema/finalverse.asset-intelligence.v1.schema.json`](../schema/finalverse.asset-intelligence.v1.schema.json)
(JSON Schema 2020-12, generated by `tools/write_schema.py`; tests validate every fixture
report against it and fail if it is stale).

## Top level

| Field | Meaning |
|---|---|
| `schema` | `"finalverse.asset-intelligence/v1"` |
| `tool` | `{name: "finalverse-asset-intelligence", version}` |
| `generated_at` | RFC 3339 UTC. `--timestamp`, then `SOURCE_DATE_EPOCH`, then the clock. **Excluded from the digest.** |
| `asset` | `file_name`, `media_type` (`model/gltf-binary` / `model/gltf+json`), `byte_length`, `sha256`, `identity` (`sha256:<hex>`), `generator` (string or null) |
| `configuration` | effective `limits`, `budget` (each value with its basis), evaluated `runtime_profiles`, `target_profile`, `embodiment_profile` |
| `validation` | see below |
| `metrics` | counts: nodes, meshes, primitives, draw_calls, vertices, triangles, degenerate_triangles, materials, textures, images, max_texture_dimension, texture_pixels, skins, joints, animations, animation_duration_s, morph_targets, external_dependencies, file_bytes |
| `findings` | ordered list of findings (below) |
| `compatibility` | `runtime` profile results and `embodiment` profile results ([S3A-EMBODIMENT-COMPATIBILITY.md](S3A-EMBODIMENT-COMPATIBILITY.md)) |
| `quality` | `categories` (7) and `tier`; `visual_evidence` when supplied |
| `proposals` | advisory improvement proposals (below) |
| `provenance` | inspector, digests of all inputs (asset, resolved dependencies, evidence), contract sources (repo/commit/path/symbol), `network_access: "none"`, `modifies_asset: false` |
| `inspection` | extracted structure (omitted with `--no-inspection`): container layout, asset metadata, extensions, scene, nodes (hierarchy and transforms), meshes/primitives (attributes, counts, bounds, morph targets), materials, textures, images (format, dimensions, digests), skins (joint names, skeleton, rest consistency), animations (duration, channels, kinds, paths, interpolation, loop closure), bounds, dependencies, capabilities. Lists are capped at `max_report_list_items` with `total`/`truncated`. |
| `report_digest` | `sha256:` of the canonical JSON of the report without `generated_at` and `report_digest` |

## `validation`

| Field | Meaning |
|---|---|
| `status` | `invalid` — any glTF 2.0 violation (`spec` class error/critical); else `refused` — security policy finding or incomplete inspection; else `valid_exceeds_limits` — a configured runtime budget is exceeded; else `valid` |
| `spec_valid`, `within_limits`, `policy_clean`, `inspection_complete` | the four independent facts behind `status` |
| `incomplete_reasons` | codes that stopped or truncated inspection |
| `target_profile_status` | status of `--target` profile, if any |
| `finding_counts`, `finding_counts_by_class`, `suppressed_repeats` | summaries |

Runtime/embodiment *incompatibility* does not change `status`: a valid asset that a
profile refuses stays `valid`, and the refusal appears under `compatibility` (and as
`FVA-CMP-001` findings when that profile is the `--target`).

## Finding

```json
{"id": "FVA-GEO-003:/meshes/0/primitives/0/indices", "code": "FVA-GEO-003",
 "name": "index_out_of_range", "category": "geometry", "class": "spec", "severity": "error",
 "component": "/meshes/0/primitives/0/indices",
 "message": "Indices reference vertices beyond the vertex count",
 "evidence": {"out_of_range": 1, "vertex_count": 24, "max_index": 99}}
```

* `id` = `code:component` — stable across runs and machines for the same asset.
* `component` is a JSON pointer into the glTF document (or `/embodiment/...`,
  `/compatibility/...`, `/quality/...` for report-level findings).
* Repeats of the same code at the same component are merged (`evidence.occurrences`);
  more than 200 distinct components per code are counted in `suppressed_repeats`.
* Ordering: severity (critical, error, warning, info), then code, then component.

Classes: `spec` (violates glTF 2.0), `security` (refused untrusted content), `resource`
(inspection safety limit), `limit` (exceeds configured runtime budget), `compatibility`
(Finalverse runtime cannot consume), `quality` (advisory).

## Proposal

```json
{"id": "P-FVA-BUF-009", "finding_ids": ["FVA-BUF-009:/accessors/36", "..."],
 "severity": "error", "category": "buffer", "class": "spec",
 "component": "/accessors/36", "components": ["/accessors/36", "..."],
 "evidence": {"message": "accessor min/max are required here", "occurrences": 38, "used_by": "/animations/0/samplers/0"},
 "action": "Write min/max for POSITION and animation input accessors.",
 "expected_impact": "Bounds and clip durations are known.", "confidence": "high",
 "required_validation": ["re-export from the authoring tool and re-run finalverse-asset validate"],
 "advisory": true, "modifies_asset": false}
```

One proposal per finding code (repeats grouped under `components`); profile (`FVA-CMP-*`)
and embodiment (`FVA-EMB-*`) proposals are per rule and name the failed rule.
`confidence` is `high` for deterministic specification checks and `medium` for
heuristics and provisional profiles.

## Quality

`quality.categories`: `geometry_integrity`, `material_completeness`,
`animation_integrity`, `embodiment_compatibility`, `runtime_complexity` (method
`deterministic`) and `visual_reference_alignment`, `artistic_coherence` (method
`evidence`). Each has `score` (0..1 or null), `status` (`assessed`, `not_assessed`,
`not_applicable`), `explanation` and `basis`. Scoring:

* integrity categories: 1.0 minus a penalty per distinct defect code at its worst
  severity (critical 1.0, error 0.35, warning 0.1), capped at 0.5 if any error;
  accessor findings caused by animation samplers count against animation integrity;
* material completeness: fraction of a six-item checklist (explicit materials, base
  colour, metallic/roughness, normals, complete texture dependencies, UV sets), capped by
  material findings;
* runtime complexity: 1.0 up to 50% of the tightest budget, linearly 0 at 200%;
* embodiment: only with `--embodiment`; 0 if a required rule fails, otherwise
  0.6 + 0.4 × fraction of recommendations met.

`quality.tier`: `certified` (highest tier whose criteria all hold), `deterministic_ceiling`
(Q0/Q1 reachable without evidence), `next_tier`, `next_tier_blockers`, full `criteria`.

| Tier | Additional criteria |
|---|---|
| Q0 Placeholder | inspection complete; glTF-valid and policy-clean |
| Q1 Stylized prototype | within budget; geometry ≥ 0.8; materials ≥ 0.6; animation ≥ 0.8 if animated |
| Q2 Production stylized | ≥ 2 verified renders; geometry ≥ 0.95; materials ≥ 0.8; alignment and coherence ≥ 0.6 |
| Q3 Cinematic stylized | ≥ 4 renders; ≥ 1 human assessment; materials = 1.0; textured; alignment and coherence ≥ 0.75 |
| Q4 High-fidelity realistic | ≥ 6 renders; declared style `realistic`; PBR texture set; alignment and coherence ≥ 0.9 |

Thresholds are S3-A proposals for review; they are constants in `quality.py`.

### Visual evidence — `finalverse.visual-evidence/v0` (provisional)

```json
{"schema": "finalverse.visual-evidence/v0", "asset_sha256": "<sha256 of the asset>",
 "style": "stylized | realistic",
 "renders": [{"path": "renders/front.png", "sha256": "<hex>", "view": "front", "renderer": "blender-eevee"}],
 "assessments": [{"assessor": "human:alice", "kind": "human | model",
                  "visual_reference_alignment": 0.8, "artistic_coherence": 0.75,
                  "renders": ["<render sha256>", "..."]}]}
```

Render paths resolve inside the evidence file's directory; each file must exist, match its
`sha256` and be a recognized image; assessments must cite verified render digests. Any
error rejects the whole file (`FVA-QLT-001`) and subjective categories stay unassessed.

## Configuration files

Budget (`--budget`): `{"name": "...", "max_triangles": 50000, "max_joints": {"value": 64, "basis": "..."}}`
for any of `max_triangles, max_vertices, max_file_bytes, max_draw_calls, max_materials,
max_joints, max_animations, max_morph_targets, max_texture_dimension, max_nodes`. Unknown
fields are rejected.

Limits (`--limits`): any field of `Limits` (see [S3A-SECURITY.md](S3A-SECURITY.md)).

## Versioning

* Additive changes (new optional fields, new codes, new profiles) keep `v1`.
* Removing or changing the meaning of a field or code requires `v2`.
* `tool.version` identifies the implementation; consumers must key on `schema`.
