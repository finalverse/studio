# S1 → S2 handoff

Read [S1 acceptance](S1-ACCEPTANCE.md), provider architecture, executable protocol,
MCP and security documents with the external delivery receipt before starting S2.
S1 is an isolated local authoring milestone; no merge, push or deployment occurred.
Keep the S0 app/source acceptance and Core adapter pinned separately. No S2, V1 or
new Civilization milestone is authorized by this handoff alone.

Extend the closed creation language through typed, bounded operations. Reuse the
same proposal store, approval boundary, scene identities, cancellation and worker
supervision for UI and MCP. Expand scene/revision coverage with each capability;
do not silently accept rigs, constraints, material graphs or drivers that this
initial profile cannot inspect or bound. Preserve safe basenames and independent
Genesis candidate validation/publication. Model failures must remain visible.

S1 handles primitive creation, applied bevel, transforms, Principled presets,
camera/light creation, linear transform keyframes, Eevee preview, editable save
and S0 GLB candidate export. It does not yet implement procedural architecture,
trees, rigging, skinning, retargeting, textures, Geometry Nodes, visual model review
or an autonomous refinement loop. S2 should add one complete asset workflow with
measured, bounded revisions. V0 must independently compare Studio and Infinity;
a Studio preview is not evidence of equivalent Infinity rendering.

Honor E1's distinct residents/archetypes and identity contracts. Lumi is a flying
spirit, not a humanoid walker. Studio cannot change founder canon, persistent
memories, institutional authority, resource balances or world revisions by
exporting an asset. Civilization policy authorizes, MutSea commits, Genesis and
SpatialDB publish, Infinity renders, and WorldLine records through accepted
contracts. Keep these authorities separate from local artist approval.

Retain exact actual model/version/latency/failure receipts. Local Gemma and Qwen
were inventoried; Maple remains disabled by the user's choice. Remote gateway and
OpenAI-compatible real-provider acceptance require configured endpoints. Codex
and Claude client examples use documented MCP interfaces; distinguish the actual
SDK client test from unexecuted proprietary-agent sessions. This development app
is unsigned/not notarized and retains the reduced S0 Eevee/Metal build profile.
